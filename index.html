Security architecture

Protection you can describe precisely

PrivateVault is designed around explicit formats, strict parsing, authenticated state transitions, and honest compatibility boundaries.

01

Create a credential

New vault and backup passwords must be 8–127 UTF-16 code units and include an uppercase letter, a lowercase letter, a number, and a symbol. Existing valid credentials remain compatible.

02

Derive a key locally

New credentials use PBKDF2-HMAC-SHA256 with 600,000 iterations, a unique random 32-byte salt, and a 256-bit derived key.

03

Encrypt and authenticate

Newly written PVL2 vault files use chunked AES-256-GCM. Current-format PVMD metadata uses a separate versioned AES-256-GCM envelope.

04

Commit verified state

Writes, restores, and migrations stage and verify candidates before transactionally making them authoritative.

Technical specification

Current formats, without inflated claims

The app does not claim hardware backing, StrongBox, guaranteed erasure, or unbreakable protection. It states what the implementation actually does.

PVL2

Vault files

Chunked AES-256-GCM with fresh nonces, structural authenticated data, ordered chunks, and strict truncation and trailing-data checks.

PVMD v2

Vault metadata

A versioned AES-256-GCM envelope protects entries, relationships, active blob references, and repository state with authenticated headers.

PVBAK4

Portable backups

New encrypted backups use a fixed, versioned backup KDF profile and authenticated structure. Supported PVBAK1–3 backups remain restorable.

KESTORE

Biometric unlock

Password-first enrollment wraps active key material with an authentication-bound Android Keystore key used through BiometricPrompt. PrivateVault never receives biometric templates.

Useful by design

Privacy that still works like a practical file vault

Both editions share the same core cryptographic formats and local-first security model. PRO adds workflow and authorization features without changing that foundation.

CAP

Capture directly

Capture photos, videos, and audio into app-private staging before encrypted vault import. PRO adds higher-quality controls and built-in video and audio playback.

LOG

Local activity history

Review an encrypted local activity log after authentication. The Android apps do not upload activity history.

BIO

Fast, optional unlock

Enable biometric unlock only after password authorization. Android performs biometric matching; PrivateVault does not store biometric data.

RST

Verified restore

Backup content is staged, authenticated, integrity-checked, and transactionally activated. Foreground progress and safe cancellation help avoid ambiguous partial state.

LCK

Session controls

Use password unlock, optional biometric unlock, automatic background locking, and immediate lock controls. Repeated failures are locally rate-limited.

EXP

User-controlled export

Export, share, or open a temporary decrypted copy only when you choose. Once outside the vault, that copy is no longer protected by PrivateVault encryption.

Know the boundary

Strong local controls. Honest external limits.

Inside the vault

Current-format files and metadata are authenticated and encrypted. Operations verify candidate state before activation.

Outside the vault

Exported, shared, or externally opened decrypted copies are controlled by the destination app or storage provider.

On your device

Android security, storage health, available space, malware status, and device configuration remain part of the overall risk.

In your hands

Keep passwords and verified backups safe. The developer has no server-side password reset or recovery access.

Built to move forward safely

Current protection, with deliberate legacy compatibility

Supported older vault files, metadata, password verifiers, and PVBAK1–3 backups remain readable. Migration paths authenticate and verify replacements before authority changes; existing external backups are not silently rewritten.
