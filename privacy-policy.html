Overview

PrivateVault and PrivateVault PRO are offline Android file vaults. Their current manifests request neither INTERNET nor ACCESS_NETWORK_STATE. Vault contents, passwords, keys, backups, and local activity records are not sent to a developer-operated app server.

Data Collection

The Android apps do not include advertising, analytics, telemetry, remote crash-reporting, cloud-sync, remote-licensing, or runtime-download SDKs.

The app does not intentionally collect:

  • Photos, videos, audio, or documents stored in your vault
  • Vault passwords or encryption keys
  • Contacts, messages, call logs, or location
  • Advertising identifiers or behavioral analytics
  • Usage tracking or crash analytics

Permissions and File Access

PrivateVault and PrivateVault PRO request permissions for user-selected features. Media and file access are used to import, preview, encrypt, decrypt, export, or manage files that you choose.

  • READ_MEDIA_IMAGES, READ_MEDIA_VIDEO, and READ_MEDIA_AUDIO may be used for selected media operations on supported Android versions.
  • Older supported Android versions may use legacy read-storage permission.
  • Android file picker access may be used so you can choose documents or folders.
  • CAMERA and audio-recording permission may be requested for direct capture; PRO also uses camera access for Scan-to-PDF and optional Intrusion Detection.
  • Notification permission may be requested for foreground operation progress where Android requires it.
  • Biometric permission supports optional Android biometric authorization.

The apps request no Internet or network-state permission. This reduces the apps' remote-exposure surface but does not control Android itself, external apps, exported copies, destination storage, or a compromised device.

How Is Data Used?

Files you select are processed locally for encryption, decryption, capture, supported previews, thumbnails, search, organization, backup, restore, export, sharing, and Open with.

Both editions also maintain an encrypted local activity history that becomes available after authentication.

Sharing and Disclosure

PrivateVault and PrivateVault PRO do not upload vault contents. When you explicitly Export, Share, or use Open with, a decrypted copy is created for the selected destination. The receiving app or storage provider may retain that copy outside vault encryption. Optional external PRO Intrusion Detection copies are also decrypted files outside the vault.

Security

Newly written and migrated vault files use PVL2, a chunked AES-256-GCM authenticated format. Current PVMD v2 metadata uses a separate AES-256-GCM envelope. Supported legacy formats remain readable for compatibility.

New vault credentials use PBKDF2-HMAC-SHA256 with 600,000 iterations, a unique random 32-byte salt, and a 256-bit derived key. New PVBAK4 backups use a separate fixed profile with the same algorithm and parameter sizes. The current implementation does not use Argon2id.

Password-first biometric enrollment uses Android BiometricPrompt and an authentication-bound Android Keystore key. PrivateVault does not receive biometric templates and does not guarantee StrongBox or verified hardware backing on every device. Release builds request screenshot protection on sensitive screens, but platform and device conditions can limit it. No software can guarantee recovery from device failure, lost passwords, or pre-existing corruption.

Children's Privacy

PrivateVault PRO & PrivateVault are not directed to children under 13 and do not knowingly collect personal information from children.

Data Safety Summary

  • Data sold: No
  • Data shared by default: No
  • Data collected by a PrivateVault app server: No app server is used
  • Cloud sync: Not provided by the Android apps
  • Ads, analytics, or tracking SDKs: Not included in the Android apps
  • Internet permission: Not requested
