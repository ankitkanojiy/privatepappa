Frequently Asked Questions

Answers about the offline vault, current and legacy encryption formats, passwords, biometrics, backups, permissions, viewing capabilities, exports, and Free versus PRO features.

PRO split

What is the difference between PrivateVault and PrivateVault PRO?

Both editions use the same core cryptographic formats. PrivateVault includes encrypted import and export, password and optional biometric unlock, search, sorting, direct photo/video/audio capture, image viewing, encrypted Activity Logs, password changes, Vault Reset, backup creation, and restore during initial setup. PRO adds folders, move, rename, starring, broader local viewers, text/code revisions, selected PDF tools, Scan-to-PDF, Settings restore, vault safety checks, Data Control, optional 2FA Unlock, Panic Lock, failed-unlock camera capture where supported, and dark or automatic themes.

Offline

Is PrivateVault offline?

Yes. The current Android manifests request neither INTERNET nor ACCESS_NETWORK_STATE. Vault encryption, decryption, backup, restore, capture, and supported viewing run locally. A Play Store or website link opens outside the vault app.

No cloud

Does PrivateVault upload my files to cloud storage?

No. The Android apps contain no cloud-sync path. Vault files remain app-private unless you explicitly export, share, open, or save a backup to a destination you control.

No account

Do I need an online account to use PrivateVault or PrivateVault PRO?

No. The vault is designed for offline use and does not require a cloud account. This applies to both PRO and Free versions.

Backup

Is Backup available in PrivateVault?

Yes. Both editions create password-protected PVBAK4 backups. Free can restore a supported backup during initial vault setup; restoring from Settings in an existing vault is a PRO feature. Keep the backup password and verified backup file safe.

Upgrade

How do I move from PrivateVault to PrivateVault PRO?

In PrivateVault, create a password-protected encrypted backup. Then open PrivateVault PRO, choose Restore, select that backup file, and enter the same backup password. This lets you move your vault data to PrivateVault PRO without cloud transfer.

Restore

Can PrivateVault PRO restore a backup created in PrivateVault?

Yes. PrivateVault PRO can restore supported backups created by either edition. Use the exact backup password used during creation. Supported legacy PVBAK1, PVBAK2, and PVBAK3 backups remain restorable.

Security

What happens if I forget my backup password?

The backup password is required to restore an encrypted backup. Keep it safe. Since the app is fully offline and does not use servers, there is no server-side recovery method to reset or retrieve your password. This applies to both PRO and Free versions.

PRO upgrade

Does PrivateVault PRO replace PrivateVault?

PrivateVault PRO is for users who want advanced vault tools. You can start with PrivateVault, create an encrypted backup, and restore it in PrivateVault PRO when you upgrade.

Local processing

Are thumbnails, previews, and search processed locally?

Yes. The app processes thumbnails, indexing, previews, and organisation locally without sending vault content to external servers. This local processing design is active in both PRO and Free versions.

Permissions

Which permissions does the app use?

PrivateVault requests permissions for user-selected features, including media access, camera capture, audio recording, notifications, and biometric authentication where applicable. Older supported Android versions may use legacy read-storage permission. The apps do not request Internet or network-state permission.

Camera

When is camera permission requested?

Both editions can request camera permission for direct photo or video capture. PRO also uses the camera for Scan-to-PDF and can optionally attempt failed-unlock captures when Intrusion Detection is enabled and the device permits it.

No internet

Does the vault need INTERNET permission?

No. Neither current manifest requests Android Internet or network-state permission. This statement applies to the PrivateVault apps, not to Android itself or external apps opened from a link.

No internet

Why do permissions combined with internet access pose a risk to my privacy?

Permissions define what an app may access, while network capability affects whether an app can communicate remotely. PrivateVault reduces its own remote-exposure surface by requesting no Internet permission. This does not eliminate risks from exported copies, other apps, device compromise, operating-system behavior, or physical access.

Permissions

How does Android's Privacy Dashboard compare to true encryption and offline storage?

Android privacy indicators help show when sensitive resources are accessed. PrivateVault adds a separate local-encryption boundary for selected vault files. Neither control guarantees protection from an exported decrypted copy, a compromised device, storage failure, or an external camera.

Encryption

How are files protected?

Newly written and migrated files use PVL2: chunked AES-256-GCM authenticated encryption with fresh nonces, authenticated structural data, ordered chunks, and strict length and trailing-data checks. Current PVMD v2 metadata uses a separate authenticated AES-256-GCM envelope. Supported legacy PVLT1 files and legacy metadata remain readable.

Encryption

What specific encryption algorithms and modes are used?

Current PVL2 vault files and PVMD v2 metadata use AES-256-GCM authenticated encryption with distinct format-specific structures and authenticated data. Current formats reject failed authentication tags, inconsistent lengths, truncation, and forbidden trailing data. This detects integrity failures; it does not repair missing data.

Encryption

How are encryption keys derived and hardened?

New vault credentials use PBKDF2-HMAC-SHA256 with exactly 600,000 iterations, a unique random 32-byte salt, and a 256-bit derived key. New backups use a separate fixed profile with the same algorithm, iteration count, salt length, and key length. Password encoding and normalization behavior remain unchanged. Argon2id is not used by the current implementation.

Password

Does the app support long vault passwords?

New vault passwords, changed vault passwords, and new backup passwords must be 8–127 UTF-16 code units and contain at least one uppercase letter, lowercase letter, number, and symbol. Confirmation must match exactly. These creation rules are not applied retroactively to a cryptographically valid existing vault or backup password.

Screenshots

Are screenshots blocked?

Release builds request Android FLAG_SECURE protection on sensitive vault screens. Platform behavior, compromised devices, external cameras, and some system-level capture paths remain outside the app's control, so this is not an absolute guarantee.

Integrity

How does PrivateVault reduce corruption risk?

PrivateVault uses authenticated formats, staged candidate files, transactional metadata activation, restore preflight authentication, exact size checks, recorded digest checks where available, and deterministic cleanup/recovery rules. A candidate cannot become authoritative solely because a file exists or a journal reached a particular phase.

Import

Can I import many file types?

Yes. PrivateVault supports importing common media, documents, code files, and other user-selected files into the encrypted vault. Note that invalid or corrupted files may not be encrypted, but most valid files can be imported. Importing files is available in both PRO and Free versions.

Export

Can I export decrypted files?

Yes. Export writes a decrypted copy to the location you select. That external copy is no longer protected by PrivateVault encryption and may remain until you or the destination provider removes it.

Share

Can I share files directly from the vault?

Yes. Sharing creates a temporary decrypted app-private copy, grants access to the selected destination through Android, and schedules local cleanup. The receiving app may retain its own copy outside the vault.

Open with app

Can I open a vault file with another app?

Yes. Open with uses a temporary decrypted app-private copy and grants the selected compatible app access. PrivateVault schedules cleanup of its temporary copy, but the receiving app controls any copy it retains.

Documents

Can I view Word, Excel, PowerPoint, and PDF files?

PrivateVault PRO provides local viewers for supported PDF, DOCX, XLSX, PPTX, text/code, media, and archive content. Office support is viewing-oriented and depends on document structure, file size, available memory, and device capability; perfect Microsoft Office rendering or editing parity is not promised. Free provides built-in image viewing only.

Password files

Can I open password-protected PDFs?

Yes. Opening supported password-protected PDFs inside the vault is available in the PrivateVault PRO version, with session isolation. Passwords are not stored.

Code files

Can I view and edit code files?

Yes. Code viewing and plain-text editing of common code formats (such as JavaScript, TypeScript, C, C++, Java, PHP, Python, Kotlin, Swift, HTML, CSS, JSON, XML, YAML, and more) is available in the PrivateVault PRO version.

Images

Can I view images in the free version?

Yes. Free includes a built-in image viewer with supported zoom and pan behavior. Its built-in viewer does not extend to video, audio, PDF, Office, archive, or code/text files; those local viewers are PRO features.

Video

Can videos play in portrait and landscape?

Yes. The video player supports dynamic rotation according to device rotation without forcing horizontal orientation. Video playback is available in PrivateVault PRO only.

Scanner

Can I scan documents with the camera?

Yes. Scan-to-PDF is available in PrivateVault PRO. Results depend on image quality, lighting, document angle, available memory, and device camera capability.

APK files

Can APK files be run inside the app?

No. APK files can be inspected in read-only mode, but they cannot be executed or installed. Note that APK file inspection is available in the PrivateVault PRO version.

Performance

Is PrivateVault optimised for budget phones?

The apps use bounded and streaming processing where the source architecture supports it, but no universal performance guarantee is possible. Large, malformed, or resource-intensive files may behave differently depending on storage, memory, processor, Android version, and device hardware.

Data safety

Can encryption damage my files?

No. Encryption itself does not randomly damage files. PrivateVault uses encryption as a mathematical process — when the original file, password, encryption key, and saved encrypted data are all correct, the file can be safely unlocked again. The real risk is an interrupted or incomplete file-writing process, not encryption itself.

Data safety

What can cause file corruption during encryption?

Corruption can occur if the app is interrupted while writing a file. Common causes include: phone powering off or battery dying, storage running out, app being force-stopped or crashing, app data or vault files being deleted, cleaner apps or file managers modifying data, storage errors (SD card or internal), or a file being overwritten unsafely. In short, corruption happens when files are only partly written or altered outside the app.

Data safety

Why does a small error break the whole file?

PrivateVault uses authenticated encryption, which checks data integrity before opening a file. If even one byte is damaged, the app may refuse to open the file. This is a safety feature to prevent showing corrupted or unsafe data — it is designed to protect you, not a flaw.

Data safety

Are encrypted files more likely to corrupt?

No. Regular files may still open partially when damaged. Encrypted files cannot — if data is incomplete, they usually cannot be recovered. Encryption makes damage easier to detect, not more likely to occur.

Data safety

Can PrivateVault recover a file if encryption was interrupted?

In many cases, if the original file is still available, the safest solution is to import or encrypt it again. However, if the original was deleted and only a partially written encrypted file remains, recovery may not be possible. Authenticated encryption is designed to reject incomplete or modified data. This is why safe writing, verification, and avoiding early deletion of originals are very important.

Data safety

What should I do while encrypting large files?

For best safety during large imports: keep your phone charged, do not force-close the app, avoid restarting the phone during encryption, make sure enough storage is available, avoid using aggressive cleaner or booster apps, do not manually edit or move PrivateVault's internal app files, and wait until the operation clearly finishes. No app can safely finish writing data if the device shuts down or storage becomes unavailable at the wrong moment.

Data safety

Can low storage cause corruption?

Yes. If storage runs out, files may not be fully written and cannot be decrypted. Always ensure enough free space before importing or encrypting files, especially large ones.

Data safety

Can changing my password corrupt my files?

Password changes use a crash-recoverable transaction that stages and authenticates replacement state before committing credential authority. Do not deliberately interrupt the operation, and keep sufficient storage available. Recovery resolves authority from authenticated repository state rather than a journal phase alone.

Data safety

Can I open or edit PrivateVault files using another file manager?

No. You should not manually open, rename, move, clean, edit, or delete PrivateVault's internal encrypted files. External file managers or cleaner apps may not understand the vault structure and may accidentally remove files or metadata needed for decryption. Use PrivateVault's built-in import, export, delete, backup, and restore options instead.

Data safety

Why can't a file be opened even if it exists?

The file may exist but be incomplete or altered. PrivateVault verifies data before opening. If verification fails, it blocks access to prevent showing corrupted or unsafe content. This strict behavior is part of secure authenticated encryption.

Data safety

Is PrivateVault Free less safe than PRO?

No. Both editions use the same core vault-file, metadata, credential, verifier, and backup formats. PRO adds viewing, organization, capture, Settings, and authorization features rather than a stronger core encryption format.

Data safety

What is most important to understand about file safety?

Authenticated encryption can detect altered or incomplete current-format data, but it cannot repair missing bytes. Keep sufficient storage available, avoid modifying app-private files, retain passwords, and verify independent backups before relying on them.

Biometrics

How does Biometric Unlock protect the vault key?

Enrollment is password-first. PrivateVault then uses Android BiometricPrompt with a cryptographic object and an authentication-bound Android Keystore key to protect the active vault-key wrapper. Android performs biometric matching; PrivateVault does not receive or store biometric templates. The app does not claim that every device provides StrongBox or verified hardware backing.

Verifier

Does the password verifier authorize vault access by itself?

No. A versioned, domain-separated HMAC-SHA256 verifier provides a constant-time precheck. Successful authenticated decryption of authoritative vault metadata remains the final proof for password-derived access. Supported legacy verifier states remain compatible.

Metadata

How is the vault index protected?

Current PVMD v2 metadata uses AES-256-GCM with a fresh 12-byte nonce, an authenticated structural header, explicit version and algorithm fields, bounded lengths, and strict truncation and trailing-data rejection. Supported legacy metadata remains readable and migrates only after password-derived authority is established.

Backups

How are new encrypted backups protected?

New backups use PVBAK4 and the fixed BACKUP_PBKDF2_SHA256_V2 profile: PBKDF2-HMAC-SHA256, exactly 600,000 iterations, a fresh random 32-byte salt, and a 256-bit derived key. The current header and per-entry structures are authenticated and strictly parsed.

Deletion

Does deleting a vault item guarantee physical erasure?

No. Deletion removes the vault's encrypted copy and metadata reference through the app's normal workflow. Flash storage, filesystem behavior, device backups, and previously exported copies prevent a universal promise of physical overwrite or forensic irrecoverability.

PRO

What are Intrusion Detection and Activity Logs?

PRO can optionally attempt camera captures after a configured number of failed unlocks, subject to permission and device capability. Both editions maintain an encrypted local activity history available after authentication. Neither feature uploads data through the Android apps. Optional external Intrusion Detection copies are decrypted files outside vault encryption.

Feature Availability Note

Some advanced features depend on device capabilities, Android version, supported file types, and production build configuration. Not every feature will be available on every device or for every file format.
