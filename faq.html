PrivateVault FAQs

Clear explanations of what the Android apps do, how the current security formats work, where compatibility applies, and where the protection boundary ends.

26 questions

BasicsWhat are PrivateVault and PrivateVault PRO?

They are Android apps for importing selected files into an encrypted, app-private vault. Both editions share the same core cryptographic formats. PrivateVault is the focused free edition; PRO adds broader local viewers, organization tools, Settings restore, and additional authorization controls.

PrivacyDo the Android apps need Internet access?

No. The current manifests request neither INTERNET nor ACCESS_NETWORK_STATE. Vault encryption, decryption, backup, restore, capture, and supported viewing happen locally. If you choose a Play Store or website link, Android opens that link outside the vault app.

PrivacyDo the apps collect analytics, advertisements, or vault contents?

The Android apps do not include advertising, analytics, telemetry, remote crash-reporting, or cloud-sync SDKs. The developer does not receive vault files, passwords, keys, or local activity logs through an app server.

EditionsWhat is the practical difference between Free and PRO?

Free includes encrypted import and export, password and optional biometric unlock, search and sorting, direct photo/video/audio capture, image viewing, encrypted activity logs, deletion, password changes, Vault Reset, backup creation, restore during initial vault setup, and a light theme. PRO adds folders, move, rename, and star controls; broader media/document/archive viewers; Scan-to-PDF; higher-quality capture; Settings restore; vault safety checks; Data Control; optional 2FA Unlock; Panic Lock; and dark or automatic themes.

EncryptionHow are current-format vault files encrypted?

Newly written and migrated files use the PVL2 format: chunked AES-256-GCM authenticated encryption with fresh nonces, structural authenticated data, ordered chunks, and strict length and trailing-data checks. This protects confidentiality and detects modification or truncation in the current format. Supported unmigrated PVLT1 files remain readable.

CredentialsHow is a new vault key derived from a password?

New vault credentials use PBKDF2-HMAC-SHA256 with exactly 600,000 iterations, a unique random 32-byte salt, and a 256-bit derived key. PrivateVault does not use Argon2id in the current implementation.

CredentialsWhat password rules apply?

New vault passwords, changed vault passwords, and new backup passwords must be 8–127 UTF-16 code units and include at least one uppercase letter, lowercase letter, number, and symbol. Confirmation must match exactly. These creation rules are not applied retroactively to a cryptographically valid existing vault or backup password.

CredentialsCan the developer reset or recover my password?

No. There is no cloud account, server-side password reset, recovery key held by the developer, or remote decryption service. Keep your password and verified backups safe; losing the required password can make encrypted data permanently inaccessible.

CredentialsDoes the password verifier authorize vault access by itself?

No. A versioned, domain-separated HMAC-SHA256 verifier provides a constant-time precheck. Successful authenticated decryption of authoritative vault metadata remains the final proof for password-derived access. Supported legacy verifier states remain compatible.

MetadataHow is the vault index protected?

Current PVMD v2 metadata uses AES-256-GCM with a fresh 12-byte nonce, an authenticated structural header, explicit version and algorithm fields, bounded lengths, and strict truncation and trailing-data rejection. It protects logical entries, folders, relationships, revisions, and active encrypted-file references.

CompatibilityCan PrivateVault still open older vault data?

Yes, supported legacy vault blobs, metadata, credential descriptors, and verifier states remain readable. Where an upgrade path exists, PrivateVault authenticates and verifies the replacement before changing authority. It does not claim to reconstruct data that was already lost or corrupted before migration.

BiometricsHow does Biometric Unlock work?

Enrollment is password-first. PrivateVault then uses Android BiometricPrompt with a cryptographic object and an authentication-bound Android Keystore key to protect the active vault-key wrapper. Android performs biometric matching; PrivateVault does not receive or store fingerprint, face, or other biometric templates.

BiometricsIs Biometric Unlock guaranteed to be hardware-backed?

No such guarantee is made. Android Keystore and strong-biometric authentication are used, but the app does not attest the active key’s StrongBox, Trusted Execution Environment, or hardware security level on every device. Device security capabilities vary.

PROIs Biometric Unlock the same as 2FA Unlock?

No. Ordinary Biometric Unlock is a convenient alternative unlock path after password-first enrollment. PrivateVault PRO’s optional 2FA Unlock is a separate mode that requires both password-authorized vault proof and a strong biometric confirmation.

BackupsHow are new encrypted backups protected?

New backups use PVBAK4 and the fixed BACKUP_PBKDF2_SHA256_V2 profile: PBKDF2-HMAC-SHA256, 600,000 iterations, a fresh random 32-byte salt, and a 256-bit derived key. The current header and per-entry structure are authenticated and strictly parsed.

BackupsCan I restore older backups?

Yes. Valid supported PVBAK1, PVBAK2, and PVBAK3 backups retain their historical restore semantics, including compatibility with older passwords that do not meet today’s creation policy. Current malformed backup data is not silently retried as a legacy format.

BackupsCan the Free edition restore a backup?

Free can restore a supported backup during initial vault setup. Restore from Settings in an existing vault is a PRO feature. Both editions can create encrypted backups.

ReliabilityWhat happens if restore is cancelled or the app closes?

Restore uses app-private staging, full authentication and integrity checks, foreground progress, and transactional activation. Safe cancellation cleans partial restore state before exit. Recovery validates staged encrypted blobs before they can enter authoritative metadata. Severe device, filesystem, or low-storage failures can still occur, so keep independent verified backups.

CaptureCan both editions capture media directly?

Yes. Both editions can capture photos, videos, and audio into app-private staging before encrypted vault import. Free includes basic capture controls and built-in image viewing. PRO adds higher-quality capture controls and built-in video and audio playback. Scan-to-PDF is PRO-only.

ViewingWhich files can be viewed inside the app?

Free provides built-in image viewing. PRO provides local viewers for supported images, video, audio, text/code, PDF, DOCX, XLSX, PPTX, and archive inspection. Support is viewer-only for Office formats and varies with document structure, size, available memory, and device capability; perfect Microsoft Office parity is not promised.

ExportsDo shared or externally opened files remain encrypted?

No. When you choose Export, Share, or Open with, PrivateVault creates a temporary decrypted app-private copy, grants the selected destination access, and schedules local cleanup. The receiving app or selected storage location can retain its own copy, which is outside PrivateVault’s encryption boundary.

DisplayDoes PrivateVault prevent every screenshot?

Release builds request Android’s FLAG_SECURE protection on vault screens. Platform behavior, compromised devices, external cameras, and some system-level capture paths remain outside the app’s control, so this is a risk-reduction measure rather than an absolute guarantee.

PROWhat are Intrusion Detection and Activity Logs?

PRO can optionally attempt available camera captures after a configured number of failed unlocks, subject to permission and device capability. Both editions maintain an encrypted local activity history that is available after authentication. Neither feature uploads its data through the Android apps. If a PRO user enables external Intrusion Detection copies, those decrypted copies are stored in the selected external folder and are outside vault encryption.

DeletionDoes deletion guarantee forensic erasure?

No. Deleting an item removes the vault’s encrypted copy and metadata reference through the app’s normal workflow. Vault Reset removes PrivateVault’s local vault state. Flash storage, filesystem behavior, device backups, and previously exported copies prevent a universal promise of physical overwrite or forensic irrecoverability.

IntegrityWhat happens when encrypted data is damaged?

Authenticated formats reject failed tags, inconsistent structure, truncation, and forbidden trailing data rather than treating altered content as valid. A rejected file may remain inaccessible. Authenticated encryption detects many integrity failures; it does not repair missing data.

PerformanceWill every file work on every Android device?

No universal guarantee is possible. Encryption and restore are streaming and bounded, but very large, malformed, unusual, or resource-intensive files may fail or perform differently depending on storage, memory, Android version, and device hardware. Maintain free space and verified backups before major operations.
