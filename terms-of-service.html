PrivateVault PRO & PrivateVault App Description

PrivateVault and PrivateVault PRO are offline Android file vaults designed to encrypt selected files locally. Their current manifests request neither Internet nor network-state permission, and the apps include no advertising, analytics, telemetry, cloud-sync, or remote file-processing SDKs.

Current-format vault files and metadata use distinct AES-256-GCM authenticated formats. New vault credentials use PBKDF2-HMAC-SHA256 with 600,000 iterations, a unique random 32-byte salt, and a 256-bit derived key. The current implementation does not use Argon2id. Supported legacy vault and backup formats remain readable according to their historical semantics.

Some advanced viewing, scanning, and document features depend on bundled native components such as PDFium and OpenCV.

Key Features

  • Local encrypted file vault in both editions
  • Password and optional biometric unlock
  • Import, export, search, sorting, selection, deletion, and encrypted backups

  • Encrypted local Activity Logs

  • No cloud account or app Internet permission required
  • No advertising, telemetry, or analytics SDKs in the Android apps

Limitations

PrivateVault and PrivateVault PRO cannot guarantee that every file type will preview or render perfectly. Unsupported, corrupted, extremely large, unusual, encrypted, or password-protected files may fail to open, preview, or process.

Scan-related features may be imperfect and depend on image quality, lighting, document angle, and supported native components.

Screenshot protection and app obfuscation reduce risk but cannot provide absolute protection against rooted devices, compromised systems, external cameras, screen mirroring bypasses, malware, or advanced reverse engineering.

PrivateVault and PrivateVault PRO do not provide cloud recovery, server-side password reset, or developer recovery access. If a vault password is forgotten or lost, encrypted files may be permanently inaccessible.

Authenticated encryption can detect altered or incomplete current-format data, but it cannot reconstruct missing bytes. Staged and transactional workflows reduce ambiguous partial state; device failure, exhausted storage, filesystem errors, or deliberate interruption can still prevent an operation from completing.

Export, Share, Open with, and optional external Intrusion Detection copies produce decrypted data outside vault encryption. Deletion removes the app's encrypted copy and metadata reference but cannot guarantee physical secure erasure on flash storage.
